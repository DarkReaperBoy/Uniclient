Every denied mic permission / failed voice attempt grew the leak. | Leak class on the web voice path (reachable once a web-capable voice backend ships; voice backends are TCP-blocked today, so this was latent — but it is the only mic cleanup path in the web audio device). | Restructured startMic around per-attempt ownership: every attempt captures its own fn/setup/failed/node/stream/channels; ONE cleanup goroutine per attempt releases ALL its js.Funcs and tears down node+stream; `endMicAttempt()` is the single attempt-over transition with an identity-checked mutex claim (a late failure callback after stopMic cannot double-close). | F-89 (R3) | **Mic capture read the sample rate off the wrong JS object — and never resampled non-48 kHz buffers (audio/webaudio_js.go).** The capture callback read `ch.Get("sampleRate")` on the CHANNEL DATA (a Float32Array — no such property in a real browser) instead of the AudioBuffer: `Value.Float on undefined` panic on the FIRST real audio callback. Even if the rate had been read, it was dead: the sample bank was sliced into 960-sample "20 ms @48k" frames regardless of the actual context rate, so a browser that ignores the requested 48000 (older Safari) got pitch-shifted, time-stretched voice (~8.8% at 44.1 kHz). Latent today (web voice backends are TCP-blocked) but it is the only capture path the web device has. | Wrong-behavior + crash class on the web voice path; the wrong-object read means the mic could never have worked in a real browser at any rate. | Rate read moved to the AudioBuffer (`args[0].Get("inputBuffer").Get("sampleRate")`); the bank is now resampled from micRate to 48 kHz with streaming linear interpolation — at 48k the window collapses to a bit-exact passthrough, at 44.1k each 20 ms frame consumes exactly 882 inputs (+1-sample look-ahead, which the emission condition `int(step*959/960)+2` encodes). RED-first (js-tagged, node runner, browser-realistic fakes — channel data has NO sampleRate property): pre-fix code PANICS `Value.Float on undefined`; a non-resampling slicer would emit 18 frames for 0.4 s @44.1 kHz, the resampler 19 — TestStartMicResamplesNon48kContextRate pins 19, TestStartMicPassthroughAt48k pins the exact-48k passthrough incl. the look-ahead flush. GREEN: dev-test.sh ALL GATES GREEN (js gui+audio legs), wasm rebuilt. |
